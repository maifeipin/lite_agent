## 1. 分工、授权与阶段边界

Antigravity 负责每阶段全部范围内的实现、迁移、反例、自主修复、最终版本本地门禁和交接资料，完成约 90% 工程工作。Codex 负责独立复现、调用链与 diff 审核、补充独立反例、小范围直接修补、重新验证和收尾报告；需要生产或远程授权的工作另按用户授权执行。

90% 不是覆盖率、测试通过率或文件完成比例。不能故意留 stub、失败测试、未迁业务、失效默认配置、空壳 CI 或已知安全漏洞给 Codex。剩余 10% 是独立审查和发布核验，不是实施欠账。存在阻塞时交付“阻塞中”，不能标“阶段完成”。

阶段二和三分两次交付。阶段二交接后停止推进阶段三，等待 Codex 收尾结论和实际基线。日常代码修补、迁移顺序、参数命名等范围内选择自主处理，不逐项请求用户确认。

禁止自行 commit、push、合并、打发布 tag、配置远程保护、部署、改生产配置、重启生产或真实 IM/邮件外发。允许本地源码、隔离测试、临时数据库和假协议服务。不得 reset/clean/stash 覆盖用户修改，不读取或打印凭据，不把生产数据复制到本地。不扩展 CEO/CFO、商机系统等新业务，不修改 Parser 财务算法，不升级生产 Python 或借重构升级 SDK。

## 3. 全程不变的工程规则

- 先 rg 查调用者、配置链、测试和对外契约，再迁移；一条调用链完成反例、实现、针对性验证后推进下一条。
- 纯搬迁尽量保留算法、参数、默认值、异常语义；搬迁和新增机制分开说明。禁止同时重写业务算法。
- contracts 只含允许的标准库、类型和无副作用数据契约；core/services/公共宿主不导入 features/skills，不按业务关键词分流，不扫描业务目录。app 只按受控清单通用装配。
- 运行时一套 Agent、一套 API、一套调度/权限/投递机制；core/full 通过装配差异实现，不复制测试专用实现。
- 不削弱断言、不增加 skip/xfail 掩盖失败、不扩大架构例外、不通过全量复制 integration/依赖包假装独立。规则变更单列 diff 和 red/green 证据。
- 临时快照、日志、测试数据库放系统临时目录；长期文档和真实测试源码可入仓。禁止把私有 config/env、DB、邮件或凭据加入快照。
- 测试 patch 过期时改到注入边界，不通过 sys.modules 反查、旧 mock 兼容分支或双实现保测试。

## 4. 阶段二工作包及执行顺序

### 2-A 盘点并冻结完整模式契约

先产出 `architecture/stage-2-migration-inventory.md`，逐项记录：旧路径/符号、所有调用者、职责归属、目标路径、插件所有者、默认启用条件、配置来源、外部消费者证据、测试和状态。

覆盖所有 skills、main cron、Agent 分流、工作流、API 路由、前端页面/静态资源、CLI、shell/bat、配置与环境覆盖。不能只盘点 billing/todo/meeting。每项技能归入通用能力、业务服务或协议适配；可按粗粒度业务域合并，不要求一工具一插件，不预建空域。

建立原生产完整模式能力清单：工具名/schema/权限、命令名、URL/方法/鉴权/响应、作业 ID/表达式/时区、页面资源、配置优先级和数据路径。使用脱敏材料，禁止连接生产来做盘点。阶段一 baseline 已知不完整，本工作包必须补齐。

验收：旧能力有且只有一个去向，full manifest 与盘点逐项对应，所有遗漏明确阻塞，不把现有三个预设当完整启用集合。

### 2-B 通用注册与生命周期

在接真实业务之前完成注册所有权：工具、命令、工作流、路由、页面、作业都有实例级注册和释放机制。插件上下文暴露有限服务端口，不直接暴露完整 Agent 私有对象；配置按插件所需投影，避免不必要暴露其他插件凭据。

- 清单只含数据：稳定 ID、精确入口、依赖和启用条件；入口必须来自受控集合。None、空列表、未设置分别定义，空列表绝不回退扫描。
- 加载前验证未知入口、重复 ID、缺依赖、禁用依赖、依赖环；先拓扑验证再执行注册，错误拒绝启动。
- 同实例重复 register/start 幂等；不同实例互不污染。重名工具/命令/工作流/路由/作业报错，禁止静默覆盖。
- 单插件注册失败回滚本次已注册资源；应用启动失败回滚此前已启动插件及基础资源。释放逆序进行，个别 cleanup 失败仍继续其他释放并汇总错误。
- 定义停止后新任务拒绝、正在执行回调等待/取消和超时策略；不得丢真实发送回执或释放后重复发送。禁止残留线程、timer、调度回调。
- HTTP 框架若不支持卸路由，用关闭/重建宿主验证，不增加在线热插拔工程。

反例至少覆盖：导入前拒绝未知入口、空白名单零导入；注册到一半抛错后无残留；第二插件启动失败前一插件被释放；重名拒绝；环依赖无注册副作用；同实例重复调用；两个实例隔离；关闭期间回调；cleanup 一处失败仍释放其余资源。

### 2-C 通用服务与 SMTP 去 Parser

将通用 output/notification/cron/commands/config/permission 机制归位 services；协议发送归 integrations。迁移沿用现有算法，不引入另一套调度器或投递路径。

先产出 `architecture/smtp-config-mapping.md`：旧来源/字段、新来源/字段、env 与文件覆盖顺序、缺省、缺失错误、发送账户与收件人语义。只放字段名和占位符。核实旧配置是否依赖 Parser 私有配置；确需用户补配置时明确列出，不读取或拷贝秘密、不继续运行时借用 Parser。以注入测试配置验证兼容映射。

SMTP 协议端不导入 Parser、不改 sys.path；MailCLI 继续负责财务边界。普通回复无 SMTP 可用；显式 email 无配置真实报错。保持目的地优先级、inline/sqlite 零外发、显式 HedgeDoc 失败不回退 email、owner-only、失败止损、完整 HTML 和单次回执。

验收用假 SMTP/HTTP/IM 或注入发送器验证参数、发送次数和失败回执；不使用真实收件人。测试必须包含“Parser 路径不存在仍可平台投递”与“发送失败不可假成功”。

### 2-D 按领域迁出业务实现

依次按实际依赖迁移，各链闭环后再下一链：

| 源头 | 迁移动作 | 关键验收 |
|---|---|---|
| task_orchestrator / Agent 账单分流 | 通用 workflow registry；billing 显式登记工厂/路由 | core 无 BillingWorkflow/账单关键词分支 |
| core/billing_* 与业务转发 | 唯一实现 features/billing；内部调用改到新路径 | Parser 仍是财务权威，无复制计算算法 |
| Todo 与提醒注册 | features/todo 持有仓储与状态策略；生命周期登记作业 | notify_enabled、人工状态、周期、幂等保持 |
| core/meeting_*、review_meeting_* | features/review_meeting 持有授权、outbox、状态 | approve 不自动执行；旧 CLI/HTTP/前端契约保持 |
| scripts/review_meeting.py | 仅参数、调用、输出、退出码 | 不剩 DB/授权/会议状态实现 |
| 邮件、RSS、备份及其余 ops | 业务归 feature，协议归 integration，工具入口保留 schema/权限适配 | 所有技能有盘点记录；无暗藏业务全局 Agent |
| channels/api.py、dashboard | 公共宿主持鉴权/传输/流式，业务插件登记 adapter/页面 | URL、静态资源、错误结构、鉴权与流式保持 |

基础模型切换、会话、执行状态、通用命令仍属基础能力，不能为清目录把它们塞入业务插件。底层通用工具按依赖表归位，不为了减少行数强拆。业务模块导入不得建库、联网、启动任务；资源初始化移到 start，释放归 stop。

### 2-E 连接唯一生产装配

main 只解析参数、调用 app bootstrap、处理信号及退出码。core/full 均连接实际 AgentRuntime、会话、命令、调度与同一公共 API/IM 宿主，删除 legacy 全局 Agent 注入和默认技能盲扫的生产调用。

必须在配置示例及长期文档定义模式选择、CLI/配置/env 优先级和插件选择规则；默认 full 保持旧完整能力；core 固定零业务插件，若同时要求业务启用则明确报冲突。full 未设置插件列表采用核实后的完整默认集合；显式 [] 保持无业务；启用未知项/缺依赖拒绝。既有显式安全禁用设置不得被默认清单覆盖。

core 普通健康/会话/非流式/流式/任务状态/鉴权可用；未启用的业务路径返回原框架规定的未找到/能力未启用错误，不能 500 或 ImportError。启动顺序应使“就绪”仅在必需资源成功后可见；关闭顺序和失败策略写入文档。

### 2-F 阶段二必须通过的门禁

1. 新进程逐个导入真实插件：无文件/DB/网络/后台作业副作用，禁用插件不进入 sys.modules。
2. 合成插件仅新增自身代码和测试清单即可登记工具、命令、workflow、业务路由、作业；不得修改 core/services/公共宿主来适配测试插件。
3. 临时源码副本物理移除 features/skills/业务页面/Parser，不能访问原仓库，走 main + 实际公共宿主完成假模型普通/流式对话和鉴权；不是仅测试 create_app 返回对象。
4. 两应用实例同时存在，工具/命令/作业和关闭互不影响。启停及部分失败无残留，禁用再启用无历史事件重放。
5. 完整 full 回归、架构检查、两仓 diff 检查、本机及 Python 3.9 门禁；新测试数量按真实结果报告。
6. 基础层到现有业务的过渡依赖清零，逐条对照实际 finding 清退；受控加载与隔离测试例外单列，不能用规则更名隐藏债务。

阶段二允许阶段三完善可重复构建、CI、外部兼容清理；不允许把真实装配、业务迁出、物理缺包 smoke 或生命周期后置。

## 5. 阶段三工作包及执行顺序

### 3-A 固化独立源码与依赖清单

建立受跟踪的基础源码 manifest、基础 requirements 及生成/验证脚本。按实际导入明确公共 integration 文件及静态资源；不能整目录包含业务适配器。memory_engine 可选，禁用且缺包也可启动基础模式。不复制私人配置、业务 fixture 或全部测试。

脚本新接口先实现再写使用说明；提供 --help、错误退出码、错误路径/缺文件/越界符号链接反例。生成物在临时目录，清单不能越过仓库边界。

从仓库外 cwd、独立进程、干净虚拟环境运行，仅安装基础依赖。清空会引入原项目的 PYTHONPATH，禁止 editable install、回指原仓库软链接或全局包泄漏。记录 sys.path、模块 __file__ 和包清单，断言基础模块来源及业务模块缺席；清单遗漏、业务夹带、路径泄漏都必须失败。

基础副本与完整源码使用相同实现和宿主；完整主入口 core smoke 不允许测试替身入口。

### 3-B 行为验收矩阵闭环

产出 `architecture/kernel-acceptance-matrix.md`，每行填写真实测试文件/用例、失败反例、实测命令、结果与日志位置，不用“全量已包含”替代定位。

| 领域 | 必须保住的行为 |
|---|---|
| 账单账户 | 默认仅 163，显式 account 优先，非法范围在建库/连接前失败 |
| 同步/质量 | 单次 sync3m 与预算，revision ack；旧事件不复活 Todo；resolved/recorded 不误报 |
| 财务证据 | 重解析失败保留有效旧记录；UNKNOWN 不猜；原币证据；只读路径零写入 |
| 人工状态 | 还款显式确认，不自动已还，不恢复已删 Todo，不覆盖人工描述/关闭 |
| 账单提醒 | 权威金额>0 到账一次；真实还款日前3天起北京时间12:00每天提醒直到手动关闭；证据不足不猜日期 |
| 普通周期 Todo | 明日10:00、提前40分钟、每5分钟、提前0保持；重复扫描不重复通知 |
| notify_enabled | 默认 true；false 只抑制该 Todo 通知；派生继承，同步不覆盖，状态/周期不变 |
| 投递 | wait_delivery 看真实结果；失败释放 claim；submitted/archived 复用；inline 零外发；完整轻量结果优先原频道 |
| 通用执行 | 流式/非流式目的地、模型锁一致；execute 参数兼容；异常/预算失败唯一终态 |
| cron | HH:MM/every_minute/既有表达式、7 * * * *、跨小时同分钟、跳 tick、回拨；同槽一次 |
| 会议 | owner/私聊授权，approve 不执行，outbox 幂等，CLI/HTTP/前端不破坏 |
| 启停与权限 | 未授权在变更/发送前拒绝；失败回滚，重启不重注册，无业务数据删除/迁移 |

复用有意义旧测试，针对迁移缺口新增独立反例，不为数字复制用例。测试使用固定时钟/临时库/假发送器，避免真实睡眠或外发。

### 3-C 验证脚本及 PR CI

拆分无 Parser 基础 gate 和显式 Parser 路径的完整 gate。现有 verify_e0.py 尚无 --agent-root/--parser-root；先实现参数、旧默认兼容、路径错误测试，验证后再使用新命令。保留脱敏快照精确白名单和 Python 3.9 离线容器约束。

新增 PR 工作流，明确执行：架构检查、物理缺业务基础 gate、Agent 全量、Parser 契约、本机/CI Python 版本验证、前端相关检查。前端先核实 JS 测试入口，Node 单独安装/执行，不声称 pytest 覆盖 JavaScript。

Parser CI 使用显式固定兼容 SHA 或可验证源码 artifact；不得写“取最新”导致不可重现。缺私有仓权限/secret 应使相关 gate 明确失败或标阻塞，不能静默跳过报绿。基础 gate 必须独立运行，不受 Parser 权限影响。

Antigravity 完成 workflow 及本地等价验证，报告哪些远程 run 尚未发生；不能把 YAML 静态检查写成远程 CI 通过。远程实际运行和 required status checks 由 Codex 在有授权后验证。未运行远程项保留待核验状态，不阻塞独立代码交接，也不宣称最终验收全完成。

### 3-D 兼容与治理清退

核对 Python 导出、CLI、脚本、shell/bat、部署文档、cron/config 和静态页面调用面。内部全部改唯一实现。保留旧入口须提供确切外部消费者、同对象再导出断言、移除条件/期限；没有外部证据则删除。不恢复已删除业务命令，不加子类包装或反查 mock。

最终核心业务依赖例外零。受控加载器与临时测试 fixture 例外精确 file/rule/target/scope/max_occurrences，保留独立非法反例；记录声明数、命中数和未登记违规数，三者不可混报。

统计生产新逻辑、纯搬迁、兼容、测试/治理四类 diff，混合文件按 hunk/职责解释。生产新逻辑增幅超过本阶段基线10%时先做设计说明，给出必要性及可删除代码；不压缩格式/藏文件规避指标。

### 3-E 交接及发布准备

## 6. 每阶段交接材料（缺项不得称90%完成）

交付 `docs/agent-kernel-stage-2-handoff-YYYYMMDD.md` 或阶段三同格式报告，并把长期清单放 architecture/。

报告必须包含：
1. 两仓基线/当前 SHA、分支、status、归属边界，声明未 commit/push/部署/真实外发。
2. 工作包逐项结果，标注实测/静态推断/未验证；已知阻塞明确列出。
3. 最终依赖图、启动/关闭顺序、资源所有者、失败回滚、正在执行任务处理。
4. 对外契约与配置映射；原→新符号；完整默认能力对照和兼容保留证据。
5. 完整源码 diff：已跟踪 patch + 新文件清单及全部内容，含文件哈希；不要把私人忽略文件或 .env 打包。仅 git diff 不足以交付。
6. 四类 diff 说明、被删旧实现、逐条清退例外，以及门禁规则/白名单/CI 变更的单独索引。
7. 覆盖最终 diff 的原始日志：命令、cwd、版本、时间、退出码、通过/失败/跳过数；失败与重跑原因保留。临时日志路径失效前另交可访问的脱敏证据。
8. 负面验证结果：缺包、无原仓库泄漏、非法导入、半注册失败、重名/依赖环、实例隔离、停用不重发、零外发与权限拒绝。
9. Codex 接手清单，仅留独立复核/远程/生产核验；代码未完、门禁红灯和重大设计阻塞不能藏在“剩余10%”。

正常验证顺序：边界专项 → 相关回归 → 静态与 diff → 阶段最终全量。变更后按影响补跑，最终全量须对应交接源码；日志生成后再改源码必须标记失效并重跑受影响检查。

同一根因修补三次仍失败，保存最小复现、根因和已试方案，报告给 Codex；继续独立工作，停止依赖此阻塞的路径。权限/财务不变量退化、schema 变更或公开契约无法保持立即报告具体设计选择。
