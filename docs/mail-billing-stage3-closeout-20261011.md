## 复核结论

原交接所报的 90% 实现有可复用底座，但“用途 Gate 已进入实际读模型”和“异常解决有充分证据”的表述超过实际完成程度。本次直接补齐，未退回执行 AI 处理小改动。

发现并修正：

1. 趋势未检查入账/原币的独立来源，可能把历史默认 CNY 与无来源 JPY 当成事实。snapshot、trends 及 Agent 快照现在只汇总 extracted/rule_declared 的已知币种；其余明细保留、隔离，不参与确认合计/折算。余额缺少独立币种证据时显示 UNKNOWN。
2. 用途可用性原来仅存元数据。现在各读模型返回实际门禁及完整性标记，阻断的交易不参与趋势；部分覆盖明确标记不完整。账单余额/日期、交易覆盖和原币证据分别影响用途，不相互替代。已确认的原币样本可分析，未知样本单独排除。
3. 表头缺交易日期时会落回旧位置解析，非法原币金额又可能静默消失。补充语义区域识别和逐行诊断；冲突、未知币种文本不回退为表头币种。保留同内容多笔交易重数。
4. 名义上账单摘要解析成功、但明细重解析不完整时仍会清空旧有效交易。现保留旧明细，记录 retained_previous_transactions，并用新诊断门禁阻止其冒充本次完整趋势；合法空明细仍可整份替换。
5. CMB 旧兜底在缺还款标签时按“账单日+18 天”寻找正文日期，实际可能把账单日选成还款日。已删除无标签猜测；可靠标签无法提取、原文未提供、证据不足分别保留诊断。推算值保留推算前证据，不作为已确认还款信息。
6. 多源解决仅比较事件消失，且确认在财务保存事务之外。现要求本次正向核验具体字段、同身份/同内容、同模板、同解析代码及配置版本、revision/cycle 精确匹配，所有受影响源全部核验后才能解决。财务保存、诊断写入、解决确认使用同一个写事务；失败整体回滚。
7. 旧库缺币种来源列时 Agent 仍信任历史币种，未知明细又可能全量塞入模型。现旧数据标为未核验，模型中的明细/未知/受阻样本均受 detail_limit 限制，完整明细保留在确定性报告；未增加 LLM 调用。
8. 待还查询按银行/月份/金额合并不同邮箱、提醒输出硬写 RMB。现保留独立账单身份，按用途 Gate 检查并显示已确认币种，0 与负余额不当成还款义务。全部记录受阻时明确“不能确认是否有临期事项”，不输出绿色无事项结论。
