## 当前已完成

简单任务、TaskSpec 和 DAG Worker 已共用 `AdaptiveStepController`，但保留简单任务与 DAG 两种入口。当前版本具备：

- 软租约与不可突破的硬预算；
- 确定性进度传感（失败、空结果、短网页结果、重复调用/结果）；
- 一次受控重规划；
- 高收益续租、持续低收益提前收尾；
- 独立最终汇总保留步，汇总阶段禁用工具；
- 有界模型上下文，完整会话持久化逻辑不变；
- 决策事件进入现有 Ledger；
- 用户手动 TaskSpec 预算仍为最高优先级硬边界。

## 观察门槛

先运行 10～20 个真实长任务，或观察 3～7 天。以下指标没有明确问题时，不进入第二阶段：

- `MAX_STEPS` 或无最终答复的发生率；
- `finalize` 是否明显过早；
- `extend` 后是否获得新证据；
- 平均步骤数、Token 与执行时长是否下降；
- DAG 是否出现节点长期独占预算或关键节点预算不足；
- 重规划后答案质量是否优于直接收尾。

## 第二阶段候选（按问题触发）

### 1. Supervisor 慢路径

仅当确定性规则无法裁决、接近软上限，或 DAG 节点需要跨节点预算调整时调用。复用统一 `LLMGateway` 和 Ledger，不增加旁路模型调用。

约束：

- 每个任务最多调用 1～2 次；
- 返回严格 JSON：`extend | replan | finalize`、`grant_steps`、`instruction`、`reason`；
- 用户手动模型和预算选择优先级最高；
- Supervisor 失败时回到当前确定性规则；
- 没有线上数据证明规则不足时，不接入该调用。

### 2. DAG checkpoint 与预算再分配

只在节点完成、连续低收益、申请续租或失败恢复时形成里程碑。编排器可以回收已完成节点的剩余预算、停止低收益分支，并向未结束 Worker 注入一次纠偏指令。

暂不支持任意在线改写 DAG；只有实际任务证明固定 DAG 无法完成时再评估。

## 更后续候选（非承诺）

- 按 `research / code / ops` 配置不同阶段策略；
- Web 页面展示租约、收益判断、重规划与收尾原因；
- 人工暂停、继续或追加指令；
- 规则无法判断时的语义信息增益评估；
- 经隐私、容量和恢复需求验证后的原始证据存储。

## 明确不做

- 不为了统一而把简单任务包装成 DAG；
- 不重写当前 DAG，除非维护量或行为收益有明确数据；
- 不为每一步调用 Supervisor；
- 不用单一 Jaccard 分数代表语义价值；
- 不因可能的未来扩展提前建设通用工作流平台；
- 不新增功能只为消除极少发生、可手工处理的边界场景。

进入后续阶段前，应先附上触发该改动的真实 Ledger 样本、预期收益和新增代码量估算。
